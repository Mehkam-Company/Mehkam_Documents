# Mehkam Certificate and Recognition Template System

---

<div align="center">
  <img src="../../../../../assets/logo/png/mehkam-symbol-white-2048w.png" alt="Mehkam Logo" width="150" />
</div>

## Overview

This document defines the official certificate and recognition template system of Mehkam Holding.

The system establishes the structural and visual foundation for certificates, recognition documents, and achievement awards issued by Mehkam Holding.

The purpose of this system is to provide a consistent, formal, premium, and reusable framework for recognizing individuals and achievements across the Mehkam ecosystem.

Final visual template execution is delegated to the design phase.

# 1. Certificate System Identity

| Property         | Value                                       |
| ---------------- | ------------------------------------------- |
| Organization     | Mehkam Holding                              |
| Document Type    | Certificate and Recognition Template System |
| Primary Language | English                                     |
| Typography       | Peyda                                       |
| Visual Direction | Minimal / Luxury / Corporate                |
| Primary Colors   | Black and White                             |
| Primary Logo     | Mehkam Symbol                               |

# 2. System Scope

The Mehkam Certificate and Recognition Template System covers:

- Standard Certificates
- Recognition Certificates
- Achievement Certificates
- Corporate Recognition Documents

All certificate types must follow the same core visual identity and structural principles.

# 3. Certificate Types

## 3.1 Standard Certificate

The Standard Certificate shall be used for formal corporate certification.

It may recognize:

- Participation
- Completion
- Contribution
- Professional Achievement
- Corporate Activities

## 3.2 Recognition Certificate

The Recognition Certificate shall be used to formally recognize exceptional contribution, performance, or achievement.

The design may provide stronger visual emphasis while remaining consistent with the Mehkam identity.

# 4. Certificate Architecture

The standard certificate structure:

```text
Certificate
│
├── Mehkam Symbol
├── Certificate Title
├── Recognition Statement
├── Recipient Name
├── Achievement / Description
├── Date
├── Certificate ID
├── Signature Area
├── Authorization / Seal Area
└── Website
```

Not every certificate must contain every element.

# 5. Logo System

The primary Mehkam symbol shall be used as the main corporate identifier.

Logo usage must follow the approved Mehkam Logo System.

The logo must:

- Preserve original proportions
- Maintain sufficient clear space
- Remain visually balanced
- Use approved black or white variants

The logo must not be modified or visually reconstructed.

# 6. Typography System

The primary typeface shall be:

```text
Peyda
```

Typography hierarchy:

```text
Certificate Title
Recipient Name
Recognition Statement
Achievement Description
Metadata
Certificate ID
Signature Information
```

The recipient name should receive strong visual emphasis while maintaining the overall corporate hierarchy.

# 7. Recipient Information

The template shall provide dedicated areas for:

```text
[RECIPIENT NAME]
[POSITION / ROLE]
[BUSINESS / COMPANY]
```

Only the fields required for the certificate type should be displayed.

The master template must remain free of real employee or recipient data.

# 8. Certificate Title

The certificate title shall clearly communicate the document purpose.

Examples of title placeholders:

```text
CERTIFICATE OF ACHIEVEMENT
CERTIFICATE OF RECOGNITION
CERTIFICATE OF PARTICIPATION
```

Final wording may vary based on the certificate purpose.

# 9. Recognition Statement

The template shall provide a dedicated area for the formal recognition statement.

Example placeholder:

```text
[RECOGNITION STATEMENT]
```

The statement must remain concise, formal, and appropriate for corporate use.

# 10. Achievement Description

Where applicable, the certificate may contain:

```text
[ACHIEVEMENT / CONTRIBUTION DESCRIPTION]
```

This section should remain visually subordinate to the recipient name and certificate title.

# 11. Date and Certificate ID

The template shall support:

```text
[DATE]
[CERTIFICATE ID]
```

Certificate IDs should provide a unique reference for official records.

The visual placement must remain consistent across all certificate types.

# 12. Signature System

The certificate shall provide dedicated signature areas when authorization is required.

Supported fields may include:

```text
[SIGNATURE]
[NAME]
[TITLE]
```

The number of signature areas may vary based on certificate type.

# 13. Authorization / Seal Area

The design may include an official authorization or seal area.

Placeholder:

```text
[AUTHORIZED SEAL]
```

The area must remain clearly defined without overpowering the certificate content.

# 14. Website

The official Mehkam website may be displayed on the certificate:

```text
mehkam.ir
```

Website placement must remain subtle and consistent with the overall layout.

# 15. Layout System

The certificate master shall define:

- Page dimensions
- Orientation
- Margins
- Grid
- Alignment
- Spacing
- Content hierarchy
- Signature placement
- Metadata placement

The layout must maintain a premium corporate appearance.

# 16. Visual Style

The certificate system shall follow Mehkam visual principles:

- Minimal
- Premium
- Formal
- Structured
- Timeless
- Authoritative

The design must avoid:

- Excessive decoration
- Bright colors
- Generic certificate ornaments
- Unnecessary gradients
- Visual clutter
- Unapproved symbols

# 17. Standard Certificate Variant

The Standard Certificate shall provide a reusable master for general corporate certification.

Required components:

- Mehkam Symbol
- Certificate Title
- Recipient Name
- Recognition Statement
- Date
- Certificate ID
- Signature Area
- Website

# 18. Recognition / Achievement Variant

The Recognition / Achievement Certificate shall provide a reusable master for exceptional performance or contribution.

Required components:

- Mehkam Symbol
- Recognition Title
- Recipient Name
- Achievement Statement
- Date
- Certificate ID
- Signature Area
- Authorization Area
- Website

# 19. Print Requirements

The final certificate designs must be suitable for professional printing.

The Designer shall consider:

- Print-safe margins
- Bleed where required
- High-resolution assets
- Typography legibility
- Black and white reproduction
- Standard paper sizes

The final print specification shall be defined during design execution.

# 20. Digital Requirements

The certificate system must also support digital distribution.

Required digital characteristics:

- High-resolution PDF
- Clear typography
- Proper document margins
- Digital readability
- Consistent branding

# 21. Design Requirements

The final design system must provide:

- Figma Master Templates
- Editable components
- Standard Certificate Master
- Recognition / Achievement Master
- Reusable signature components
- Reusable metadata components

The Designer must preserve:

- Mehkam logo rules
- Typography rules
- Color system
- Minimal corporate aesthetic
- Certificate hierarchy

# 22. Production Formats

Required editable format:

```text
Figma
```

Required exports:

```text
PDF
PNG
```

Future production formats may include:

- Word
- Google Docs

# 23. Asset Structure

Certificate templates shall follow:

```text
assets/
└── templates/
    └── documents/
        └── certificates/

```

# 24. Asset Naming

Recommended naming:

```text
mehkam-certificate-[type]-[variant]-[language]-v[version]
```

Examples:

```text
mehkam-certificate-standard-master-en-v1
mehkam-certificate-recognition-master-en-v1
mehkam-certificate-achievement-master-en-v1
```

# 25. Design Execution

The following assets shall be created during the design phase:

- Standard Certificate Master
- Recognition Certificate Master
- Achievement Certificate Master
- Digital Export Templates
- Print-ready Masters

All templates must remain editable and reusable.

# 26. Completion Criteria

The Certificate and Recognition Template System is complete when:

- Certificate types are defined.
- Certificate architecture is defined.
- Logo rules are defined.
- Typography hierarchy is defined.
- Recipient information structure is defined.
- Signature and authorization areas are defined.
- Print requirements are defined.
- Digital requirements are defined.
- Asset structure is established.
- Naming convention is established.
- Design execution requirements are documented.
