# Mehkam Icon System

## Overview

This document defines the official Mehkam Holding Icon System.

It establishes the visual language, construction principles, sizing, stroke treatment, color usage, naming conventions, asset formats, usage rules, and governance requirements for Mehkam icons.

The system provides a consistent and reusable visual language across Mehkam digital products, websites, presentations, documentation, marketing materials, internal communication, and other approved brand applications.

All approved Mehkam icon assets shall comply with the standards defined in this document.

# 1. Icon System Purpose

The Mehkam Icon System exists to establish a consistent and reusable visual language for functional and informational icons across the Mehkam ecosystem.

The system is intended to:

- Provide visual consistency across Mehkam brand assets.
- Establish a recognizable Mehkam icon language.
- Reduce inconsistent third-party icon usage.
- Provide reusable production-ready icon assets.
- Support digital products and corporate communication.
- Enable scalable icon asset management.
- Maintain consistency across Mehkam brand applications.

# 2. Icon Personality

Mehkam icons shall reflect the following characteristics:

- Minimal
- Structured
- Precise
- Calm
- Professional
- Premium
- Institutional
- Timeless

Icons should communicate meaning clearly without unnecessary visual complexity.

The following visual characteristics are not part of the primary Mehkam icon language:

- Cartoon-like styles
- Playful decorative styles
- Excessive visual detail
- Hand-drawn appearance
- Three-dimensional effects
- Glossy effects
- Gradients
- Drop shadows
- Unnecessary decoration

# 3. Visual Style

The primary Mehkam icon style is:

**Minimal Geometric Outline**

Icons shall be constructed using simple geometric forms and a consistent outline treatment.

The visual language shall prioritize:

1. Semantic clarity
2. Visual consistency
3. Optical balance
4. Simplicity
5. Scalability

Icons should contain only the visual elements required to communicate their intended meaning.

# 4. Construction Grid

The master construction grid for Mehkam icons is:

| Property             | Standard   |
| -------------------- | ---------- |
| Master Grid          | 24 × 24 px |
| Safe Area            | 2 px       |
| Primary Drawing Area | 20 × 20 px |
| Perspective          | None       |

The 24 × 24 px grid is the primary reference for constructing Mehkam icons.

All master icons should be created using this grid before being adapted for other sizes.

# 5. Stroke System

The Mehkam Icon System uses a consistent outline treatment.

| Property              | Standard |
| --------------------- | -------- |
| Master Stroke         | 1.75 px  |
| Small Size Adjustment | 1.5 px   |
| Large Size Adjustment | 2–2.5 px |
| Stroke Cap            | Round    |
| Stroke Join           | Round    |

Stroke values may be optically adjusted when required for specific sizes.

Optical consistency takes priority over strict numerical consistency.

# 6. Corner System

Icons shall use restrained geometric rounding.

The preferred optical corner range is:

**2–3 px**

Corner treatment must preserve the structured and institutional character of the Mehkam visual language.

Excessive rounding that creates a playful or overly soft appearance should be avoided.

# 7. Fill System

The primary Mehkam icon treatment is outline-based.

Filled elements may be used when required for:

- Semantic clarity
- Small-size legibility
- Visual hierarchy
- Specific approved icon constructions

Filled elements must remain consistent with the geometry and visual weight of the overall icon system.

# 8. Color System

The Mehkam Icon System follows the monochromatic Mehkam visual identity.

Approved primary icon colors are:

| Variant | Color     |
| ------- | --------- |
| Black   | `#000000` |
| White   | `#FFFFFF` |

No additional colors shall be introduced into the master Mehkam Icon System without approval.

Portfolio-company brand colors shall not be incorporated into Mehkam master icons unless explicitly approved.

# 9. Supported Sizes

The primary supported icon sizes are:

- 16 × 16 px
- 20 × 20 px
- 24 × 24 px
- 32 × 32 px
- 48 × 48 px
- 64 × 64 px

The **24 × 24 px** version is the master construction size.

All other sizes should preserve the original proportions and geometry.

# 10. Naming Convention

Mehkam icon names shall use lowercase kebab-case.

The standard naming structure is:

```text
{category}-{name}
```

Examples:

```text
navigation-menu
navigation-search
navigation-home
business-building
communication-mail
technology-database
status-success
```

Color variants shall use the following structure:

```text
{category}-{name}-{variant}
```

Examples:

```text
navigation-menu-black.svg
navigation-menu-white.svg
```

Icon names shall describe the semantic purpose of the icon rather than its visual appearance.

# 12. Monochrome Variants

Each approved Mehkam icon shall support the following primary variants:

- Black
- White

Both variants shall use identical geometry, proportions, and construction.

The black variant is intended primarily for light backgrounds.

The white variant is intended primarily for dark or reversed backgrounds.

# 13. Usage Rules

Mehkam icons shall:

- Preserve their original proportions.
- Follow the approved construction system.
- Use approved monochrome colors.
- Maintain sufficient surrounding space.
- Preserve visual consistency with the icon family.
- Be used according to their intended semantic meaning.
- Use SVG assets whenever scalable output is required.

Mehkam icons shall not:

- Be stretched or distorted.
- Use unapproved colors.
- Use gradients.
- Use drop shadows.
- Use glow effects.
- Receive unnecessary decorative effects.
- Be combined with unrelated icon styles.
- Be modified in a way that breaks system consistency.

# 14. Asset Formats

The primary production format for Mehkam icons is:

**SVG**

SVG assets shall be used whenever scalable vector output is required.

PNG assets may be provided for environments where raster output is required.

Production exports must preserve:

- Approved geometry
- Stroke treatment
- Color treatment
- Proportions
- Naming conventions

# 15. Asset Structure

The Mehkam Icon System uses the existing asset structure:

```text
assets/
└── icons/
    ├── index.ts
    ├── master/
    ├── svg/
    └── png/
```

The `master` directory contains editable source assets and governing icon documentation.

The `svg` directory contains production-ready vector exports.

The `png` directory contains approved raster exports.

# 16. Quality Control

Every icon added to the Mehkam system shall be reviewed against the following criteria:

- Grid alignment
- Stroke consistency
- Corner consistency
- Optical weight
- Visual balance
- Semantic clarity
- Size legibility
- Monochrome compliance
- Naming compliance
- Export quality
- Brand consistency

An icon that fails a critical consistency requirement shall not be promoted to the approved asset library.

# 17. Asset Approval

New icons shall follow the Mehkam asset production and approval process.

The minimum approval sequence is:

```text
Concept
  ↓
Construction
  ↓
Visual Review
  ↓
Export
  ↓
Quality Control
  ↓
Approval
  ↓
Master Asset Library
```

Only approved assets may be distributed as official Mehkam brand assets.

# 18. Governance

The Mehkam Icon System is governed by Mehkam Holding.

Changes to the following require review through the Mehkam brand governance process:

- Icon construction principles
- Grid rules
- Stroke rules
- Corner rules
- Color rules
- Naming conventions
- Core icon categories
- Export standards

New icons should only be added when a legitimate recurring requirement exists.

Duplicate or unnecessary icons should not be introduced into the master library.
