# Document Types Standard

## Overview

This document defines the official documentation types used across Mehkam Holding and all subsidiary companies.

The purpose of this standard is to ensure every document has a clear purpose, structure, and classification.

A consistent document type system enables:

- Better documentation organization
- Faster document discovery
- Clear ownership
- Scalable knowledge management

# 1. Document Type Classification

Every document created inside Mehkam must belong to one official document type.

Available document types:

| Code | Document Type                |
| ---- | ---------------------------- |
| DOC  | General Document             |
| ADR  | Architecture Decision Record |
| PRD  | Product Requirement Document |
| RFC  | Request For Comment          |
| SOP  | Standard Operating Procedure |
| POL  | Policy Document              |
| REP  | Report                       |
| PLN  | Plan                         |
| LOG  | Log                          |

# 2. General Document (DOC)

## Purpose

General Documents contain informational content that does not belong to a specific specialized category.

## Usage

Examples:

- Company information
- Knowledge documents
- Internal explanations
- Technical documentation

## Naming Example

Mehkam-KNO-DOC-001-company-overview.md

# 3. Architecture Decision Record (ADR)

## Purpose

ADR documents record important technical and architectural decisions.

## Usage

Examples:

- Technology selection
- Database decisions
- Infrastructure decisions
- Architecture changes

## Required Sections

ADR documents should include:

- Context
- Problem
- Decision
- Alternatives
- Consequences

## Naming Example

Mehkam-ENG-ADR-001-database-selection.md

# 4. Product Requirement Document (PRD)

## Purpose

PRD documents define product requirements and product behavior.

## Usage

Examples:

- Product features
- User flows
- Product specifications
- Functional requirements

## Required Sections

PRD documents should include:

- Problem Definition
- Goals
- Requirements
- User Stories
- Acceptance Criteria

## Naming Example

CHASHA-PRD-PRD-001-customer-order-flow.md

# 5. Request For Comment (RFC)

## Purpose

RFC documents are used to propose changes and collect feedback before implementation.

## Usage

Examples:

- New systems
- Major improvements
- Process changes
- Technical proposals

## Required Sections

RFC documents should include:

- Proposal
- Motivation
- Technical Details
- Risks
- Discussion

## Naming Example

Mehkam-ENG-RFC-001-new-authentication-system.md

# 6. Standard Operating Procedure (SOP)

## Purpose

SOP documents define repeatable operational processes.

## Usage

Examples:

- Deployment process
- Hiring process
- Support process
- Operational workflows

## Required Sections

SOP documents should include:

- Purpose
- Scope
- Responsibilities
- Steps
- Validation

## Naming Example

Mehkam-OPS-SOP-001-production-deployment.md

# 7. Policy Document (POL)

## Purpose

Policy documents define official rules and organizational standards.

## Usage

Examples:

- Security policies
- Governance rules
- Engineering standards
- Company rules

## Required Sections

Policy documents should include:

- Purpose
- Scope
- Rules
- Responsibilities
- Enforcement

## Naming Example

Mehkam-SEC-POL-001-security-policy.md

# 8. Report (REP)

## Purpose

Report documents store analytical information and recorded results.

## Usage

Examples:

- Market research
- Financial reports
- Performance analysis
- Business reviews

## Required Sections

Reports should include:

- Objective
- Data
- Analysis
- Results
- Conclusion

## Naming Example

Mehkam-STR-REP-001-market-analysis.md

# 9. Plan (PLN)

## Purpose

Plan documents define future activities, objectives, and execution strategies.

## Usage

Examples:

- Roadmaps
- Project plans
- Growth plans
- Launch plans

## Required Sections

Plans should include:

- Goals
- Timeline
- Resources
- Milestones
- Risks

## Naming Example

Mehkam-STR-PLN-001-product-roadmap.md

# 10. Log (LOG)

## Purpose

Log documents maintain historical records of events and changes.

## Usage

Examples:

- Decision logs
- Change logs
- Release history
- Activity records

## Required Sections

Logs should include:

- Date
- Event
- Owner
- Description

## Naming Example

Mehkam-OPS-LOG-001-release-history.md

# 11. Document Type Rules

## Rule 1

Every document must have exactly one document type.

## Rule 2

Document type must match the document purpose.

## Rule 3

Creating custom document types requires approval from Mehkam Documentation Team.

## Rule 4

Existing document types should be reused whenever possible.

# Final Statement

The document type system ensures that Mehkam Holding and all subsidiary companies maintain a scalable, organized, and professional documentation ecosystem.

Every document must follow the official document classification defined in this standard.
